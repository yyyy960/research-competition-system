# 科研竞赛管理系统项目测试计划

## 1. 测试目标

### 1.1 业务目标

1. 保障四类科研成果（学科竞赛、大创项目、软件著作权、学术论文）全流程业务逻辑准确，成果提交、两级审核、撤回、归档、退回流程流转无异常；
2. 确保前端 OCR 证书识别、CCF 期刊匹配、成果 CSV 导出、文件上传下载等特色功能稳定可用；
3. 保证多角色权限隔离生效，学生、科研秘书、学院领导、系统管理员操作边界不越权。

### 1.2 质量目标

1. 系统上线后 P0 级重大缺陷数为 0，严重级别缺陷修复率 100%，核心功能可用性 99.9%；
2. 核心接口单交易响应时间＜300ms，批量导出、批量文件上传无内存溢出；
3. 页面兼容性达标，主流浏览器、PC 端页面布局无错乱，交互无阻塞。

### 1.3 合规与安全目标

1. 满足校园数据安全规范，学生科研成果、个人信息脱敏存储、传输加密；
2. 无 SQL 注入、XSS、越权访问、文件上传漏洞，通过基础安全扫描；
3. 操作日志完整留存，满足校内系统审计追溯要求。

## 3. 测试时间计划（4 个月）

### 第 1 月：测试准备与单元、接口测试阶段

1. 需求文档研读、测试需求拆解、全模块测试用例设计；
2. 测试环境搭建、模拟测试用户数据（学生 / 秘书 / 领导 / 管理员）批量导入；
3. 接口自动化脚本开发（Postman）、后端单元测试配合开发验证；
4. Mock 第三方依赖（CCF 期刊库、OCR 离线引擎）。

### 第 2 月：集成测试 + 核心功能测试阶段

1. 用户认证、四类成果 CRUD、两级审核核心流程全量手工测试；
2. OCR 识别、文件上传、重复检测特色功能专项测试；
3. 第一轮接口集成测试，校验多模块数据联动一致性；
4. 第一轮基础性能压测，定位慢查询接口。

### 第 3 月：系统全量测试阶段

1. 全流程回归测试，覆盖所有 P0/P1 用例；
2. 安全渗透测试、浏览器兼容性专项测试；
3. 个人中心、数据仪表盘、系统后台管理功能完整测试；
4. 第二轮性能优化复测、大数据量导出压力测试。

### 第 4 月：UAT 验收 + 上线准备阶段

1. 组织高校业务人员开展用户验收测试；
2. 生产环境数据脱敏演练、部署验证；
3. 全量缺陷复盘、遗留风险评估；
4. 输出完整测试总结报告、自动化脚本归档、操作手册校验。

## 6. 测试策略

### 6.1 功能测试策略

1. **正向流程测试**：完整覆盖成果提交、审核、导出、OCR 识别标准正常场景；
2. **边界值测试**：文件大小边界（0/20MB）、成果名称长度上限、获奖时间极值、登记号格式边界；
3. **异常场景测试**：网络中断、上传图片损坏、OCR 识别无文字、重复提交、中途撤回、审核退回修改重提；
4. **跨模块数据一致性测试**：成果主表、审核记录表、时间线表、文件关联表数据联动校验，增删改后数据无脏数据；
5. **角色权限分层测试**：分学生 / 秘书 / 领导 / 管理员独立账号遍历全部菜单、接口，验证越权拦截；
6. **特色功能专项策略**：OCR 分清晰 / 模糊 / 黑白彩色图片分类测试；CCF 期刊精确 / 模糊匹配双场景测试；CSV 导出校验中文、逗号、换行特殊字符。

### 6.2 接口测试策略

1. 所有前后端交互 API 100% 覆盖，成果新增、审核、文件、OCR 接口重点校验；
2. 资金 / 成果类核心接口做幂等性测试（重复提交不生成重复数据）；
3. 异常入参校验：空参数、超长文本、非法格式参数、篡改成果 ID 请求；
4. 多表关联接口返回字段完整性校验，无敏感信息泄露。

### 6.3 安全测试策略

1. 全覆盖 OWASP TOP10 基础漏洞扫描；
2. 业务逻辑漏洞专项：水平越权（查看他人成果）、垂直越权（学生执行审核接口）、重复提交刷数据；
3. 前端输入框 XSS 过滤校验；
4. 文件上传黑名单校验（exe、bat 等恶意文件拦截）；
5. JWT 过期、伪造 Token 拦截校验，密码密文存储校验。

### 6.4 自动化测试策略

1. P0 核心业务流程自动化（成果提交→审核→归档全链路，占核心流程 40%）；
2. 每日开发构建自动执行接口回归脚本，输出接口报错报告；
3. 高频操作（导出、OCR 识别、登录）自动化监控，快速回归迭代版本。

## 8. 准入、暂停、准出标准

### 8.1 测试准入标准

1. 需求规格说明书、数据库设计文档、接口文档完成评审并基线化；
2. 开发完成单元测试，单元测试通过率＞90%；
3. 提测版本冒烟测试全部通过（20 条核心流程用例）；
4. 测试环境部署完成，四角色测试账号、基础模拟数据准备就绪；
5. OCR、文件上传、审核等核心特色功能无阻塞性 bug。

### 8.2 测试暂停标准

1. 阻塞性缺陷超过 3 个，无法开展核心流程测试；
2. 系统频繁崩溃，每小时报错 / 页面卡死＞3 次；
3. 核心审核、成果提交、OCR 功能缺失，测试无法推进；
4. 测试环境数据库 / 文件存储故障，超过 2 小时无法恢复。

### 8.3 系统测试准出标准

1. 全部 P0、P1 级测试用例执行率 100%，执行通过率 100%；
2. 缺陷修复标准：致命 / 严重缺陷修复率 100%，一般缺陷修复率≥90%，遗留缺陷全部出具风险评估与临时规避方案；
3. 性能指标达成：并发、接口响应、导出大数据量均达到预定指标；
4. 安全扫描无高危、中危漏洞，低危漏洞完成修复或风险备案；
5. 浏览器兼容性测试全部通过，OCR 特色功能稳定可用；
6. 校方业务人员 UAT 验收测试签字通过；
7. 全套测试报告、缺陷分析报告、性能安全报告评审完成。

### 8.4 上线准出标准

1. 预发布环境完整功能验证、数据导出、OCR 识别全流程验证通过；
2. 系统操作日志、异常监控告警正常启用；
3. 线上回滚方案验证完成；
4. 管理员、师生操作手册校验无误，校内使用培训材料准备完成；
5. 所有遗留低风险缺陷完成上线备案。
